# Corpus

The 220-problem financial reasoning corpus described in §4.1 of the paper, and
the chain that produced it.

| | |
|---|---|
| `trainingset.json` | **The corpus.** 220 problems: `number`, `problem`, `answer`. |
| `problemset.json` | 1,574 candidates across 294 functions, before review. |
| `function-library.json` | The 295 seed functions that survived curation. |
| `build/` | The construction chain. See [build/README.md](build/README.md). |
| [`DATASHEET.md`](DATASHEET.md) | Provenance, composition, and limitations. **Read this before using the corpus.** |
| [`LICENSE-DATA`](LICENSE-DATA) | CC BY 4.0. |

```python
import json
problems = json.load(open("data/trainingset.json"))
problems[0]["problem"]   # the scenario
problems[0]["answer"]    # the exact expected answer, e.g. "$21,600"
```

Answers are exact strings with rounding stated in the problem text. Grading
against them goes through an LLM equivalence judge
(`pipeline/eval_script.run_eval`) so formatting and rounding differences do not
count as errors; a deterministic parser would also serve.

## What is not here

Intermediate build artifacts — `answers.json`, `grades.json`,
`functions-graded.json` and the rest — are regenerated by `build/` and are
gitignored. Run logs (`reasoning_log.jsonl`) are likewise run output, not source.
